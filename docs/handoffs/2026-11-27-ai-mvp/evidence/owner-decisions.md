# AI MVP 운영 연결 인계 후보

AI Development Main은 AI 오케스트레이션, 제품 검증, 합성·실사용 근거, 최종 독립 검수를 계속 소유한다. Normal Main에 요청하는 것은 운영 인증·저장 계약의 연결이다. 이 문안은 승인이나 외부 전송 기록이 아니다.

| 항목 | 추천 결정 | 수락 증거 |
|---|---|---|
| Finance 일지 운영 연결 | 내부 Finance→Shared AI 한 경로에 서비스 인증서 주체와 복기 작업 권한을 결속한다. 신뢰 루트·갱신·철회 책임을 Normal Main이 정하고, Finance가 원본 소유권과 전송 허용 필드·revision을 먼저 검사한다. 실제 사용자 일지 전송은 허용 필드·보존·로그 정책 승인 뒤 연다. | 양방향 인증 성공, 미등록/철회/무권한 서비스는 본문 수신 전 거부, 잘못된 일지/필드/revision 참조 거부, 실제 화면에서 허용·거절·결과 폐기 |
| Finance 대화 저장 | 미저장 세션 기본, 사용자가 명시 저장한 대화만 영속, 삭제 즉시 접근 차단. 소유자·테넌트 범위, 삭제/백업/복원, 보존 기간과 재전송 키 수명을 확정한다. 매 턴 정책 검사와 검증된 답변만 저장한다. | 로그인 사용자 간 격리, 서버 재시작·재로그인 후 이어가기, 삭제 후 늦은 응답·복원 재노출 차단, 허용된 내용만 저장 |

Carelog RPL-62 HOLD, 운영 저장 BLOCKED, 운영 Memory OFF, OpenDART 후속 범위를 유지한다. 실제 데이터 사용·운영 활성화·PR 병합·배포는 각 권한자가 별도 승인한다. 미수행 검증은 NOT_RUN으로 기록한다.

## 출시 연결 착수 조건

- Normal Main이 로그인 주체·테넌트·철회·전체 로그아웃, Shared AI 서비스 인증, Carelog 메모 공통 revision 및 저장 의도 계약의 정본 위치와 승인 revision을 반환한다.
- AI Development Main은 정본 계약을 기준으로 Finance 일반 분석·일지·대화와 Carelog 방문 준비·명시 저장을 병렬 연결한다. 이미 승인된 로컬 통합 범위와 통과 증거를 재사용한다.
- 후보 SHA와 합성 사용자 화면을 고정하고 실제 연동 대상의 환경과 데이터 허용 범위를 확인한다. Hosted CI와 외부 독립 검수 1회를 거친 뒤 승인된 대상에서 병합·배포·수락 검증을 이어간다.
- Finance Docs #25 `db1e4476`과 Carelog Architecture #6 `ec75eacb`는 운영 제안 Draft다. Finance Docs #24와 Carelog Architecture #5는 기존 제한 범위에 대한 근거로 유지한다.
