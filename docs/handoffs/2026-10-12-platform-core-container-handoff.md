# Luna Max Handoff: Platform Core Container Build Foundation

## Selected Task

Fix the earliest verified containerization blocker in Platform Services: the Core Docker
build context omits the Shared Audit Gradle project files even though the project is
included by settings and required by the app. This task directly unblocks a deployable
Platform Core image, preserves all service and domain contracts, can be tested locally,
and can ship as an isolated PR.

## Target

- Repository: ranikun-labs/platform-services
- Target branch: main
- Reviewed base HEAD: 02821f230ce828ceffd6f126b056d3a018abd509
- Work class: AI-WRITE
- Issue: https://github.com/ranikun-labs/platform-services/issues/20

## Evidence

- platform-core/settings.gradle.kts includes :shared-audit.
- platform-core/app/build.gradle.kts declares implementation(project(":shared-audit")).
- platform-core/app/Dockerfile copies app, identity, and shared-ai build files and sources,
  but omits shared-audit/build.gradle.kts and shared-audit/src.
- Docker image build was not run during this documentation task. The missing module inputs
  are a static, repository-verified blocker; confirm by building after the fix.

## Files to Inspect / Expected Change Surface

- platform-core/app/Dockerfile — copy the Shared Audit module build file and source tree
  into the build stage using the existing Docker build context conventions.
- docker-compose.yml — inspect its Platform Core build context only to confirm the Dockerfile
  change remains compatible; modify only if the build context is demonstrably wrong.

Inspect the actual files on the target branch before editing. Keep the patch limited to the
container build inputs needed for this included Gradle module.

## Implementation Scope

1. Add all required Shared Audit Gradle project inputs to the Core image build stage.
2. Preserve Gradle settings, module dependency, Java version, application behavior, image
   entrypoint, and all HTTP / JSON, SSE, identity, token, and audit contracts.
3. Verify the Core image builds from the repository's existing build context.
4. Record the resulting image build command and outcome in the PR.
